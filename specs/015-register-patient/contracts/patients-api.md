# Contract: `POST /api/patients` (US-01)

Register one patient with its initial triage level. Clinical endpoint: `Depends(get_current_user)`
plus the nurse role check (research R4).

## Request

```http
POST /api/patients
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{ "name": "Paciente Ficticio Siete", "age": 40, "sex": "female", "triage_level": 3 }
```

| Field | Type | Rule |
|---|---|---|
| `name` | string | Required; surrounding spaces removed; then 1–100 characters |
| `age` | integer | Required; strict whole number (no `"40"`, `40.5`, `true`); 0–130 |
| `sex` | string | Required; `female`, `male` or `other` |
| `triage_level` | integer | Required; strict whole number 1–5 (1 = Triage I, most urgent) |
| *(any other field)* | — | Not allowed → 422 (includes `identifier`, `admitted_at`, `status`) |

## Responses

Checks run in this order: sign-in (401) → role (403) → body (422). One exception: a body that is
not valid JSON at all (cannot be parsed) is rejected with 422 before sign-in is checked, because
the framework reads the body first. Nothing is stored in either case.

### 201 Created

```json
{
  "identifier": "PAT-007",
  "name": "Paciente Ficticio Siete",
  "age": 40,
  "sex": "female",
  "triage_level": 3,
  "status": "active",
  "admitted_at": "2026-11-20T15:04:05.123456Z"
}
```

`identifier` is generated by the system (next after the highest `PAT-<digits>`, never below
`PAT-007`). The internal `id` is never returned. One `initial` triage event is stored with
`occurred_at` equal to `admitted_at` (see [data-model.md](../data-model.md)).

### Errors (fixed messages; never the submitted values or internal details)

| Status | When | Body |
|---|---|---|
| 401 | No token, invalid or expired token, unknown user | `{"detail": "Not authenticated"}` + `WWW-Authenticate: Bearer` (existing TS-06 behavior) |
| 403 | Signed in with a role other than `nurse` | `{"detail": "Only nurses can register patients"}` |
| 409 | The generated code conflicted twice (one retry already done) | `{"detail": "Could not assign a patient code; try again"}` |
| 422 | Body invalid (missing, wrong type, out of range, unknown field) | `{"detail": [{"type": "...", "loc": ["body", "<field>"], "msg": "..."}]}`: existing TS-06 handler; no `input`, no `ctx` |
| 503 | `DATABASE_URL` not set, or a database error other than the code conflict | `{"detail": "Service unavailable"}`; logged by error type only |

Nothing is stored on any error answer.

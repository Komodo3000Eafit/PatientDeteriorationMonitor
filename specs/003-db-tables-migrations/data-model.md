# Data Model: Database Tables and Migrations (TS-03)

Five tables, defined in `backend/app/models.py` and created by the migration `backend/migrations/versions/0001_initial_schema.py`. Types are PostgreSQL. Constraint names follow the naming convention in [research.md](research.md) R5.

Common rules:

- `id`: `INTEGER GENERATED BY DEFAULT AS IDENTITY`, primary key `pk_<table>`.
- `NOT NULL` unless the column is marked *nullable*.
- Timestamps are `TIMESTAMP WITH TIME ZONE` (UTC); "default now" = `server_default now()`.
- Every foreign key is `ON DELETE RESTRICT` (FR-005).
- Allowed-value lists are `VARCHAR` + a named `CHECK ... IN (...)`, not PostgreSQL enums (D-08).

## users

A clinician account (accounts are created in TS-06).

| Column | Type | Rules |
|---|---|---|
| id | integer identity | PK |
| username | varchar(50) | unique `uq_users_username` |
| password_hash | varchar(255) | hash only; there is no plain-text password column (FR-008) |
| full_name | varchar(100) | |
| role | varchar(10) | `ck_users_role`: `doctor`, `nurse` |
| created_at | timestamptz | default now |

## patients

A synthetic triaged patient (D-09; no real-identity columns, FR-013).

| Column | Type | Rules |
|---|---|---|
| id | integer identity | PK |
| identifier | varchar(20) | synthetic code, e.g. `PAT-001`; unique `uq_patients_identifier` |
| name | varchar(100) | synthetic name |
| age | smallint | `ck_patients_age`: 0–130 |
| sex | varchar(10) | `ck_patients_sex`: `female`, `male`, `other` |
| admitted_at | timestamptz | default now |
| triage_level | smallint | `ck_patients_triage_level`: 1–5 (1 = most urgent) |
| status | varchar(20) | `ck_patients_status`: `active`, `discharged`; default `active` |

State: `active` → `discharged`. Patients are discharged, not deleted.

## vital_signs

One set of NEWS2 inputs (D-08) for a patient.

| Column | Type | Rules |
|---|---|---|
| id | integer identity | PK |
| patient_id | integer | FK → `patients.id` (`fk_vital_signs_patient_id_patients`) |
| recorded_at | timestamptz | default now |
| respiratory_rate | smallint | breaths/min; `ck_vital_signs_respiratory_rate`: ≥ 0 |
| spo2 | smallint | %; `ck_vital_signs_spo2`: 0–100 |
| on_oxygen | boolean | supplemental oxygen yes/no |
| systolic_bp | smallint | mmHg; `ck_vital_signs_systolic_bp`: ≥ 0 |
| heart_rate | smallint | beats/min; `ck_vital_signs_heart_rate`: ≥ 0 |
| consciousness | varchar(1) | `ck_vital_signs_consciousness`: `A`, `C`, `V`, `P`, `U` (ACVPU) |
| temperature | numeric(3,1) | °C; no bounds (spec Assumptions) |

## triage_events

A change of (or the first) triage level, with its reason (constitution Principle V).

| Column | Type | Rules |
|---|---|---|
| id | integer identity | PK |
| patient_id | integer | FK → `patients.id` |
| occurred_at | timestamptz | default now |
| previous_level | smallint, *nullable* | `ck_triage_events_previous_level`: 1–5 when present; empty for `initial` |
| new_level | smallint | `ck_triage_events_new_level`: 1–5 |
| score | smallint, *nullable* | `ck_triage_events_score`: ≥ 0 when present |
| reason | text | which vitals and rules produced the change |
| source | varchar(10) | `ck_triage_events_source`: `initial`, `automatic`, `manual` |
| created_by_id | integer, *nullable* | FK → `users.id`; empty for system events |

## alerts

A notice to clinicians about a patient.

| Column | Type | Rules |
|---|---|---|
| id | integer identity | PK |
| patient_id | integer | FK → `patients.id` |
| created_at | timestamptz | default now |
| severity | varchar(10) | `ck_alerts_severity`: `low`, `medium`, `high` |
| message | text | |
| status | varchar(20) | `ck_alerts_status`: `open`, `acknowledged`; default `open` |
| acknowledged_by_id | integer, *nullable* | FK → `users.id` |
| acknowledged_at | timestamptz, *nullable* | |

State: `open` → `acknowledged` (sets `acknowledged_by_id` and `acknowledged_at`; done by US-07).

## Relationships

```text
users 1 ──< triage_events.created_by_id      (optional)
users 1 ──< alerts.acknowledged_by_id        (optional)
patients 1 ──< vital_signs.patient_id
patients 1 ──< triage_events.patient_id
patients 1 ──< alerts.patient_id
```

Plus Alembic's own `alembic_version` table (one row: the current revision).

## Migration

- Revision `0001_initial_schema`, `down_revision = None`.
- `upgrade()`: create `users`, `patients`, then `vital_signs`, `triage_events`, `alerts` (parents first), with every constraint named as above.
- `downgrade()`: drop the five tables in reverse order (children first).
